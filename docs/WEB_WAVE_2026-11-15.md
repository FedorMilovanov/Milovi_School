### 2.2 `853d86f` — один сериализатор JSON-LD вместо шести копий
Все шесть страниц (`index`, `canon`, `history`, `about`, `methodology`,
`articles/[id]`) содержали одинаковый хелпер:

```ts
const safeJsonLd = (v) => JSON.stringify(v).replace(/</g, '\\\\u003c')
```

В TS-литерале `'\\\\u003c'` — это два символа (обратный слэш + `u003c`), поэтому
в вывод уходил `\\u003c`, а JSON декодировал его в **литеральный** `\u003c`
вместо `<`. Сегодня это не ломает ничего только потому, что ни в одном
JSON-LD-значении корпуса нет символа `<`. Это дефект, а не «стиль»: первая же
кавычка, `<` в подписи к изображению или в FAQ-ответе — и все краулеры получают
испорченный текст.

Сделано: `src/utils/jsonld.ts` (`serializeJsonLd`) — экранирует `<`, U+2028,
U+2029 как валидные JSON-escape, значения для краулеров не меняются, но байты
больше не могут закрыть `<script>` раньше времени. `materials.astro` (единственная
корректная копия) тоже переведён на общий хелпер.

Попутно, в том же графе `Article`: убран `articleBody` — там лежали первые 1500
символов markdown-исходника, обрезанные посреди предложения и с синтаксическим
мусором. `wordCount` остался. JSON-LD статьи: 3.4 KB → 1.9 KB, ×158 страниц.

### 2.5 `20d914d` — без JavaScript видны заголовки и цифры
**Новый подтверждённый дефект, найденный в этой волне.** В статическом HTML
лежал контент, который затем прятался:

| Где | Что было скрыто |
|---|---|
| `dist/index.html` | `<h1>…Pâtisserie</h1>`, лид, CTA-строка, 4 карточки статистики — `style="opacity:0"` |
| `dist/canon/index.html` | `<h1>LE CANON SUCRÉ</h1>`, label, intro, count — `style="opacity:0"` |
| `src/styles/global.css` | `.reveal { opacity: 0 }` без единого JS-скоупа |

Источник — `initial={{opacity:0}}` framer-motion: он сериализуется в SSR-разметку.
Без скриптов (или если гидратация не завершилась) H1 главной и весь hero Canon
были невидимы, а LCP-текст не мог отрисоваться до старта React.

Сделано: pre-paint скрипт в `BaseLayout` помечает `html.js`; `.reveal` и новый
`.enter-up` (вход hero) скоупятся на `html.js` и
`prefers-reduced-motion: no-preference`; home-hero (label/H1/лид/CTA) и canon-hero
переведены на CSS-анимацию с `--enter-delay`/`--enter-shift`; четыре статистики
получили `initial={false}` (правдивые числа видны в HTML).

Инлайн `opacity:0` в HTML: `/canon/` 4 → **0**, `/` 9 → 2, и оба остатка
осознанные: фон-hero на `0.8` (видим) и мобильный нижний бар — это JS-хром,
его кнопки без JS неработоспособны, поэтому он скрыт, а навигацию без JS даёт
футер.

Отвергнутая альтернатива: оставить анимацию и погасить её через
`html:not(.js) [style*="opacity:0"] { opacity:1 !important }` — страница
по-прежнему строилась бы вокруг скрытого состояния.

- **Экранирование JSON-LD — латентный дефект, не живая поломка.** Отдельно
  фиксирую: `grep u003c dist` даёт 0 и до фикса; проверять надо семантикой
  (Node `JSON.parse` значения), а не поиском подстроки.
- **«Broken image на главной» — не дефект сайта.** `public/images/canon-sucre/canon-gateway-hero.webp`
  генерируется `prebuild` из `assets/canon-gateway-hero/*.b64` (SHA-проверка
  внутри). Мои прямые вызовы `astro build` (обход Node-гейта) `prebuild`
  не запускали — отсюда падение аудита на базовой сборке. На штатном
  `npm run build` ассет на месте (77 970 B, SHA совпадает).

## 4. Новые fail-closed гейты

### `scripts/audit_no_js.py` (новый, в `npm run audit:site`)
1. на каждой ключевой странице ровно один `h1`, и он не скрыт инлайн-стилем
   (`opacity:0` / `visibility:hidden` / `display:none`) ни у себя, ни у предка;
2. бюджеты видимого текста (главная 500, canon 1200, materials 1500 слов) +
   обязательные редакционные маркеры; сравнение без пробелов, потому что
   `LuxuryText` рендерит заголовки по буквам;
3. ни один `<h1..h3>/<p>/<li>` не может стоять на `opacity:0` (кроме `<nav>` —
   это JS-хром);
4. в собранном CSS каждое правило `.reveal`/`.enter-up` с `opacity:0` обязано
   иметь префикс `html.js`.

**Доказательство, что гейт падает:** на сборке базы (`e8e4ddd`) — 18 нарушений,
включая скрытые `h1` на `/` и `/canon/`; на текущей сборке — 16 285 проверок, PASS.

### `scripts/audit_seo.py` (+25 464 проверки: 5 380 → 30 844)
- инлайн JSON-LD: ни одного сырого `<`, ни одного двойного `\\u003c`, ни одного
  разобранного значения с литеральным `\u003c`;
- каждый `<img src>`, `og:image`, `twitter:image` — на нашем origin; каждый
  `image:loc` в sitemap начинается с `https://french.milovicake.ru/`.

**Доказательство, что гейт падает:** инъекция старого escape в `/index.html` →
`JSON-LD contains a double-escaped '\\u003c'` + `string value contains a literal
escape instead of '<'`.

## 6. Ограничения доказательной базы

- **Браузера нет.** Playwright/Chromium в песочницу не устанавливаются, egress
  ограничен. Поэтому нет Lighthouse (LCP/CLS/TBT), нет прогона axe/WCAG, нет
  скриншота «JS выключен». Утверждение про no-JS доказано разметкой и CSS
  (инлайн `opacity` отсутствует, правила скоупятся на `html.js`) и закреплено
  автоматическим гейтом, но не живым браузером. Это надо закрыть в CI
  (`deep-polish-audit.yml` / `gallery-quality.yml` уже гоняют браузерные пробы).
- **IndexNow** проверен офлайн-инъекцией; реальная отправка возможна только в
  деплое.
- **`npm run build` vs прямой CLI.** Мои сборки запускались в обход Node-гейта
  (`node /tmp/run/astro.mjs build`), поэтому `prebuild`/`materialize` вызывались
  вручную. HTML это не меняет (ассет — отдельный файл), но в отчёте фиксирую,
  чтобы цифры не расходились с CI.
- Изменения в `src/data/historyArticles.ts` и `docs/HISTORY_EDITORIAL_PLAYBOOK.md`
  — ровно одна ссылка на медиа + размеры; текст статьи не тронут.
