# Историческая библиотека /history/ — editorial contract

**Раздел:** `https://french.milovicake.ru/history/`; категория: `histoire-culinaire`.
Цель — публиковать настоящие исторические исследования в существующей SSG-библиотеке, а не создавать посты-копии или карточки-заглушки.

## Как добавлять новые материалы

1. Проверить право редакции на публикацию/адаптацию исходного текста. Не копировать чужие статьи целиком. Источники и цитаты проверять по первичным объектам: музейный каталог, библиографическая запись, архив, официальная история дома, затем надёжные исследования.
2. Установить устойчивый `Article.id`, заголовок, информативный excerpt, `category: 'histoire-culinaire'`, реальную дату публикации, авторство/редакционную ответственность, источники и даты исправлений. Не датировать материал датой сборки.
3. Для самостоятельной новой статьи добавить полный `Article` в `src/data/historyArticles.ts` (или выделить в собственный модуль и подключить к `src/data/library.ts`). Legacy-модель `articles.ts + deepContents.ts + articleExpansions.ts` поддерживается только для существующей части корпуса; нельзя обойти её invariant частично созданной записью.
4. Ключевое изображение — собственный/разрешённый файл с известными размерами и provenance. `imageAlt` описывает содержание, `imageCredit` честно сообщает об AI. Подлинная гравюра/архивный документ не заменяется генерацией; каждый объект проверять отдельно по лицензии и URL.
5. Новая статья с категорией `histoire-culinaire` **автоматически** попадёт в `/history/` → «Новые исследования». Для постоянного размещения в курируемой секции перенести ID в `src/data/history.ts`; не дублировать ID. Нельзя добавлять фиктивные/неопубликованные ID.
6. `/articles/<id>/` — единственная HTML-страница статьи в школе. При синдикации Telegraph, Telegram, VK сохранять исходную публикацию, избегать повторной автоматической отправки и указывать provenance; SEO canonical новой школьной статьи остаётся собственным URL.
7. Запустить `npm run validate`, затем browser QA для mobile/desktop, keyboard/reduced-motion, SEO и визуальной верстки; через PR и exact-SHA production proof. До live proof нельзя объявлять «вышло на сайте».

## Non-negotiable gates

- Нет разных опубликованных страниц для одного `id`; нет дублей курируемых ID и несуществующих article routes.
- No client-side full article corpus import. `/history/` полностью серверно отрендерена, без зависимости от hydration для списка ссылок.
- В HTML: H1, canonical, OG image, ItemList, BreadcrumbList, crawlable links, sitemap; у статьи History `isPartOf` на `/history/`.
- Верификация нового content/изображений/ссылок — отдельная от факта merge/deploy и от индексации поисковиками.
